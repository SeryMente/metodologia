El puente local utiliza OAuth Authorization Code + PKCE.

La custodia local del refresh token utiliza DPAPI CurrentUser.

No se deben extraer cookies ni credenciales de navegadores.

No se deben copiar secretos de Vercel a Windows.

Un perfil Windows o SID diferente requiere un proceso de autorización y aprovisionamiento propio. No supongas que el estado DPAPI de otra máquina o usuario es portable.

## 9.7. Operaciones con efectos

`jules_create_session`, `jules_send_message` y `jules_approve_plan` son operaciones de escritura.

No reintentes a ciegas operaciones POST no idempotentes cuando el resultado sea ambiguo.

La aprobación de planes requiere:

- Sesión actual.
- `plan_id` actual.
- `plan_sha256` cotejado.
- Estado `AWAITING_PLAN_APPROVAL`.
- Doble preflight.

Jules no ofrece una precondición atómica por plan o ETag. Persiste, por tanto, un riesgo residual T22 de carrera entre la última lectura y la escritura.

La doble comprobación reduce el riesgo, pero no lo elimina. Nunca presentes una garantía atómica que la API upstream no ofrece.

Las pruebas de lectura no deben crear sesiones reales, enviar mensajes ni aprobar planes.

La aceptación de escrituras reales requiere autorización específica del operador.
