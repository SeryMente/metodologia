## 1\. Integración real Agentes ↔ CLI ↔ RDC

### Resultado: desconectados operativamente; compatibilidad parcial de campos

El wrapper `tools/Invoke-ProductDesignStore.ps1` no recibe una conversación, no invoca perfiles ni reconoce agentes. Recibe una operación y un JSON que alguien debe construir y entregarle.

Sus parámetros reales son\:

| Parámetro | Función |
|--------|--------|
| `-Operation` | Operación: `Initialize`, `SaveCycle`, `Search`, `RebuildIndex`, `Verify`, `RestoreVersion`, `ListProjects` o `ShowSession`\. |
| `-WorkspaceRoot` | Directorio donde se guardan los datos. Es obligatorio. |

| `-PayloadJson` | JSON de entrada de la operación. |
| `-TestMode` | Habilita el confinamiento de pruebas sintéticas. |
| `-ProtectedWorkspaceVerified` | Declaración del invocador de que el workspace protegido está verificado. No consulta ni acredita EP. |

El wrapper transforma esos parámetros en argumentos para Python y entrega el JSON por `stdin`\. No tiene API, servidor, listener, conexión con ChatGPT ni mecanismo propio de captura de la salida del agente.

## 3\. Auditoría de solidez del código

### Esquema real implementado

Una precisión importante: **SQLite no es la fuente canónica de los registros**\. La fuente canónica son los JSON; SQLite es un índice derivado.

| Elemento | Implementación real |
|--------|--------|
| Proyecto | `projects/<project_id>/project.json` |
| Sesión | `projects/<project_id>/sessions/<session_id>/session.json` |
| Ciclo | `projects/<project_id>/sessions/<session_id>/cycles/<number>-r<revision>.json` |
| Biblioteca | `library/library.sqlite` |
| Índice | Una tabla virtual FTS5 llamada `library_fts` |

La tabla FTS5 contiene\:

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS library_fts USING fts5(
    project_id UNINDEXED,
    session_id UNINDEXED,
    cycle_id UNINDEXED,
    version_id UNINDEXED,
    project_title,
    topic,
    goal,
    content,
    tags,
    tokenize='unicode61'
)
```

No hay tablas relacionales convencionales, claves primarias, claves foráneas ni un modelo de relaciones SQL. Aunque se activa `foreign_keys=ON`, no hay claves foráneas definidas.

El índice contiene una entrada por versión/ciclo. No indexa cada idea como entidad independiente ni implementa el modelo relacional de reutilización entre proyectos que describe EP-TASK-010.

### Transacciones, atomicidad y concurrencia

**Aspectos que sí existen\:**

- Escritura JSON mediante archivo temporal en el mismo directorio.
- `flush`, `fsync` y `os.replace`\.
- Conexión SQLite con `timeout=15`\.
- `PRAGMA synchronous=FULL`\.
- Transacción SQLite para operaciones del índice.
- Bloqueo externo mediante creación exclusiva de `.product-design-writer.lock`\.
- SHA-256 e idempotencia por contenido.
- Versiones anteriores conservadas; restaurar crea un ciclo nuevo.

**Límites detectados\:**

1. **No existe una transacción única del ciclo.** El ciclo, `session.json`, `project.json` y el índice se actualizan en pasos separados. Cada JSON puede escribirse atómicamente, pero no hay atomicidad entre los cuatro componentes.
2. **La idempotencia tiene una carrera de concurrencia.** La lectura de la revisión existente ocurre antes de adquirir el bloqueo de escritura. Dos procesos concurrentes pueden leer el mismo estado y competir por escribir la misma revisión.
3. **El bloqueo no tiene recuperación de bloqueo obsoleto.** Si el proceso muere antes de eliminar `.product-design-writer.lock`, futuras operaciones pueden quedar bloqueadas hasta que alguien intervenga.
4. **El índice puede quedar desactualizado sin fallar el guardado.** Si falla la actualización FTS5 después de guardar los JSON, el código puede devolver `ok=true` e indicar `index_updated=false`\.
5. **La verificación no compara el índice completo con las fuentes.** Comprueba hashes de ciclos y conteos, pero no realiza una comparación íntegra de filas FTS5 contra todos los registros canónicos ni ejecuta `PRAGMA integrity_check`\.
6. **La protección de rutas no está completamente cerrada para todos los archivos descendientes.** Hay lecturas de ciclos obtenidos por `glob` que no aplican consistentemente la validación de ruta segura. Debe revisarse el tratamiento de symlinks y condiciones TOCTOU.
7. **No hay cobertura de concurrencia real ni de recuperación de crash.** Las 12 pruebas no ejercitan dos escritores simultáneos, bloqueo abandonado o interrupción entre escrituras de manifiestos.
8. **La búsqueda es más limitada que el requisito documental.** FTS5 busca texto y tags, pero no ofrece todos los filtros previstos por madurez, tipo, autor, estado y relaciones entre proyectos.
9. **No existe un mecanismo completo de reanudación o Save As.** `ShowSession` permite consultar la sesión; no implementa por sí mismo la reanudación operativa de un agente ni el flujo de guardar una ideación como proyecto independiente.
10. **El wrapper no tiene timeout de proceso.** Además, consume `stdout` y después `stderr` de forma secuencial, lo que puede bloquearse si el proceso hijo llena el buffer de error.

### TODO, stub, mock y funciones vacías

La inspección estática de `product_design_store.py`, `Invoke-ProductDesignStore.ps1` y `test_product_design_store.py` dio\:

| Comprobación | Resultado |
|--------|--------|
| `TODO`, `FIXME`, `XXX`, `stub`, `mock`, `NotImplemented` | Sin coincidencias |
| Funciones Python vacías detectadas por AST | 0 |
| Errores de sintaxis PowerShell | 0 |

Esto no significa que no haya casos borde pendientes. Los problemas de concurrencia, bloqueo obsoleto, atomicidad entre archivos, validación de enlaces y verificación FTS5 son brechas funcionales aunque no estén marcadas con `TODO`\.

**Conclusión del punto 3\:** el código funciona para el conjunto de operaciones sintéticas probado, pero no tiene todavía garantías suficientes para denominarlo un almacén durable de producción.
